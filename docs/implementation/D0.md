# D0 — Authenticated GitHub remote transport

Task: `crisp-meadow-36.13`. Implementation checkpoint: `8bdbbdf3b43c789fdd184ef0383a95de1b9f81b5` (before final documentation and required squash). Source base: `e05d4e6`. Final delivery SHA is recorded in the task close receipt; the delivered commit contains this evidence and the same tested implementation. No required D0 source/specification changes were deferred.

Named administrator profiles now select a file-backed SSH deploy key or HTTPS token per central binding. Both paths authenticate advertisement, fetch, existing-branch push, new-branch push and reconciliation. Profiles are exact-remote scoped. Worker bindings remain credential-free. New branches use the existing typed SHA-1 `expected_old` with forty zeroes and an exact absent-ref lease; configured target allowlists still apply.

Credential material is not placed in command arguments, environment, bindings, journals or diagnostic messages. SSH has an explicit identity, no agent, batch mode, strict pinned hosts and no inherited SSH config. The HTTPS helper reads the token file only on credential `get`, checks HTTPS/host/path and does not store credentials. Redirects are disabled and TLS verification remains enabled. Material files require service ownership and private permissions; symlinks, malformed profiles and cross-remote reuse refuse explicitly. The remote runner retains the ordinary subprocess deadlines, admission limits and output bounds without widening the public environment override allowlist.

Authentication/authorization and SSH host verification denial return `remote_auth_failed`. Before push dispatch, the failed operation releases its publication hold and records a terminal failure. After dispatch, the journal remains pending with `remote_effect_unknown=true` and retry advice `reconcile_first`; exact replay cannot resend the push. Unknown transport effects remain fenced.
