# aq-git v0.2.0 Release Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task in the assigned isolated worktree. Steps use checkbox syntax for tracking. AQ owns integration; do not independently publish the default branch.

**Goal:** Publish a verifiable v0.2.0 source archive, Linux x86_64 executable and build record, qualified with Git 2.43.0 and 2.56.0.

**Architecture:** Keep the existing protocol and runtime behavior. Version the existing workspace, qualify it using both Git executables, export a committed source tree and build using the exact bookworm image. Reuse scripts/release-manifest for independent binary/source hashes and supplement it with explicit build provenance and archive checksums.

**Tech Stack:** Rust 1.96.1, Cargo locked workspace, Git 2.43.0/2.56.0, Docker bookworm builder, Python 3, SHA-256, GitHub releases.

**Spec:** AQ task eager-grove-45.2 (A3a), imported from aq-server/docs/superpowers/plans/2026-11-02-v2-full-application-tasks.yaml, A3a section.

## Global Constraints

- **Builds:** each repository builds and tests alone. No sibling path dependencies, no submodules, no floating branches in release inputs. Rust uses the committed lockfile with `--locked` (ecosystem §4, E1).
- **Secrets:** no secrets in templates, manifests, prompts, logs, assignment JSON or task descriptions (P8, SBX9). Node, backend, Git remote and supervisor credentials never enter sandboxes (SBX17).
- **Explicit refusals:** unsupported required capabilities refuse explicitly; nothing silently degrades (SBX13, SBX19).
- **Definition of done:** `cargo fmt --check`, `cargo clippy --locked --all-targets -- -D warnings` and `cargo test --locked` pass for the touched Rust workspaces. Evidence goes in `docs/implementation/A3a.md`, recording exact commands, environment, commit and remaining limits. Changes are pushed through the project's integration policy. Prior qualification statements are not reused for changed code.
- No aq-server re-pin or Dockerfile changes, performance target work, power-loss rehearsal or repository-profile widening.
- Builder: `rust:1.96.1-bookworm@sha256:a339861ae23e9abb272cea45dfafde21760d2ce6577a70f8a926153677902663`.
- Git input: upstream `git-2.56.0.tar.xz`, SHA-256 `26c56c296b38c0695b26fa95f475f1d01704d2d38e73465ca30b0b2f5dc789d3`.
- The binary must require at most GLIBC 2.34. Preserve development-manifest certification limits; publication does not certify P1–P7, host power loss or hosted transports.
